The error "Liquid error (layout/theme line 85): Error in tag 'section' - 'header' is not a valid section type" means Shopify's copy of the theme has no section registered under that name. This is a packaging problem, not a code problem.

The cause is the zip command in `replit.md` and `rafrikid-theme/README.md`:

    zip -r rafrikid-theme.zip rafrikid-theme/

Run from the workspace root, this nests every file one level down inside a `rafrikid-theme/` folder. Shopify requires `assets/`, `config/`, `layout/`, `locales/`, `sections/`, `snippets/` and `templates/` to sit at the ROOT of the zip.

Please make these four changes:

1. Replace the zip command in both `replit.md` and `rafrikid-theme/README.md` with:

    cd rafrikid-theme && zip -r ../rafrikid-theme.zip . -x ".*" -x "__MACOSX/*" -x "*/.DS_Store"

2. Add a `build:theme` script to the root `package.json` that runs exactly that command, so the zip is always built the same way. Do not build it from the workspace root.

3. Add `rafrikid-theme.zip` to `.gitignore` and remove the committed copy with `git rm --cached rafrikid-theme.zip`. The committed zip is stale — it was built before the locale JSON fix — and uploading it ships the old code.

Fix a settings namespace mismatch: `config/settings_data.json` stores `logo_text`, `phone_number` and `announcement_text` as theme settings, but `sections/header.liquid` reads them as section settings via `section.settings.logo_text` etc. Those are different namespaces, so the section always falls back to its schema defaults. Either move these three values into a `current.sections.header.settings` block in `settings_data.json`, or drop them from the theme settings entirely and keep them section-only.
